# Day 12 — ROWS BETWEEN for Range Calculations\n\n## Window frame\nA window frame determines which rows participate in a window calculation for the current row.\n\n## Syntax\n```sql\naggregate_function(column) OVER (\n    ORDER BY ordering_column\n    ROWS BETWEEN start_boundary AND end_boundary\n)\n```\n\n## Common boundaries\n| Boundary | Meaning |\n|---|---|\n| `UNBOUNDED PRECEDING` | From the first row in the partition |\n| `2 PRECEDING` | Two physical rows before the current row |\n| `1 PRECEDING` | One physical row before the current row |\n| `CURRENT ROW` | The current row |\n| `1 FOLLOWING` | One physical row after the current row |\n| `UNBOUNDED FOLLOWING` | Through the final row in the partition |\n\n## Examples\nPrevious two rows plus current:\n```sql\nSUM(amount) OVER (ORDER BY sale_id ROWS BETWEEN 2 PRECEDING AND CURRENT ROW)\n```\nRunning total:\n```sql\nSUM(amount) OVER (ORDER BY sale_id ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)\n```\nCurrent plus next two rows:\n```sql\nSUM(amount) OVER (ORDER BY sale_id ROWS BETWEEN CURRENT ROW AND 2 FOLLOWING)\n```\n\n## PARTITION BY\n`PARTITION BY` creates independent groups; the frame calculation restarts within each partition.\n```sql\nSUM(amount) OVER (PARTITION BY region ORDER BY sale_id ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)\n```\n\n## Important distinctions\n- `ROWS` counts physical rows in the ordered result.\n- `RANGE` uses ordering values and peer rows to define a frame; it is not simply a fixed row count.\n- `ORDER BY` determines the sequence used by the frame. Add a unique tie-breaker when ordering values can tie.\n- At partition boundaries, only available rows are included.\n
